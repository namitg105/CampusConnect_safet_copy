  📌 DAY 3: DATA LAYER ENHANCEMENTS
  
  ✅ WHAT WAS ADDED:
  
  1. New Query Methods in PostRepoImpl:
     • getCollegeFeedByTag(collegeId, tag)
       - Filters posts by college AND tag (#Badminton, #Seniors, etc.)
       - Query: collection('posts')
               .where('collegeId', ==, collegeId)
               .where('tag', ==, tag)
               .orderBy('createdAt', descending: true)
     
     • getTopVotedPosts(collegeId)
       - Sorts by upvotes instead of creation date (for "Top Voted" tab)
       - Query: collection('posts')
               .where('collegeId', ==, collegeId)
               .orderBy('upvotes', descending: true)
  
  2. Vote Management (Firestore Transactions):
     • upvotePost(postId, userId)
       - Stores user vote in subcollection: /posts/{postId}/votes/{userId}
       - Atomically increments/decrements post upvotes
       - Prevents double voting via transaction
       - Data structure:
         posts/
           └── {postId}/
               ├── votes/
               │   └── {userId}: { voteValue: 1, votedAt: timestamp }
               └── upvotes: 42
     
     • downvotePost(postId, userId)
       - Similar to upvote but stores voteValue: -1
     
     • removeVote(postId, userId)
       - Deletes user's vote and reverts upvote count

  3. VoteEntity Model:
     - Holds userId and voteValue (1, -1, or 0)
     - Tracks when vote was cast

  KEY SECURITY CONCEPT:
  ⚠️  Firestore Transaction ensures atomicity:
      If 2 users vote simultaneously, both operations complete correctly.
      Without transactions, race conditions could cause vote count inconsistency.

  🔐 SECURITY RULES CHECKLIST (Day 10):

  ⚠️  Add these Firestore Security Rules to prevent data leaks:

  match /posts/{document=**} {
    allow read: if request.auth.token.email.endsWith(resource.data.collegeId);
    allow create: if request.auth.token.email.endsWith(request.resource.data.collegeId);
    allow update: if request.auth.uid == resource.data.authorId;
    allow delete: if request.auth.uid == resource.data.authorId;
  }

  This ensures:
  ✓ Users only see posts from their college
  ✓ Users can only post if their email matches college domain
  ✓ Only post author can edit/delete their post
